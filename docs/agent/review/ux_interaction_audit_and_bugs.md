# 编辑器交互体验、流畅度问题与 Bug 审计记录

> 用途：记录对 Inkpoint 编辑器全功能上手体验、内容输入、光标移动、组件交互的实测审计结果。从第一性原理出发，记录发现的交互卡点、不流畅体验及 Bug 的详细复现步骤与源码根因分析，为后续优化提供依据。

---

## 1. 体验总览

本次体验覆盖了桌面端编辑器的核心日常写作与交互全链路：
- **文本与 Markdown 语法输入**：标题（H1-H6）、正文段落、无序列表、有序列表、任务列表、引用块、分割线；
- **行内标记与智能配对**：粗体、斜体、删除线、行内代码、中英文混排、成对符号包裹；
- **GFM 表格交互**：单元格就地编辑、Tab / Shift-Tab 单元格导航、Enter 下移/退出、Pipe 字符转义、行/列块手柄操作与对齐切换、整表原子选中与删除；
- **代码块与混合语言**：代码输入、自动缩进、语言切换（TypeScript / Python 等）、代码复制；
- **行首块级控件与手柄**：行首 `⋮` 块操作菜单（添加块、折叠、H1-H6 / 正文切换）、六点手柄 pointer 拖拽重排、标题折叠与展开；
- **侧边栏与大纲**：文件树检索、大纲目录层级渲染、点击跳转与滚动高亮跟踪；
- **命令面板与模式切换**：`Cmd/Ctrl+K` 命令面板搜索与执行、WYSIWYG ↔ 源码模式无缝切换。

### 核心结论
- **底层架构极其扎实**：单一 CodeMirror 6 View 使得在 WYSIWYG 模式与源码模式之间切换时，选区、历史撤销栈（Undo History）、滚动位置均百分之百保持，完全没有双引擎同步的丢字、重刷或焦点丢失问题。
- **表格与块拖拽体验优秀**：表格始终以可视化网格呈现且单元格就地编辑，内置 `\|` 转义保护；块拖拽指示线与落点计算精准。
- **存在数个破坏写作心流的关键 Bug 与交互卡点**：列表与引用无法通过两次回车退出、表格末尾 Tab 无法自动增行、空光标成对符号缺少自动闭合、全局命令面板与插入链接快捷键冲突等。

## 2. 发现的 Bug 记录与根因分析

### Bug 1: 列表项在空内容时回车无法退出列表（无限生成空列表项）

- **严重程度**：高（严重破坏 Markdown 列表日常输入习惯）
- **现象描述**：
  在输入列表项（无序列表 `- `、有序列表 `1. `、任务列表 `- [ ] `）后按 `Enter`，会换行并生成新的列表前缀；但当新行处于**空列表项**（仅有 marker，尚未输入正文）时，用户再次按 `Enter`（期望退出列表、回到普通段落空行），编辑器**不会退出列表**，而是**无限继续插入新的空列表项**（例如 `- \n- \n- `、`1. \n2. \n3. `）。用户被“困”在列表中，必须手动按 Backspace 才能删掉前缀。
- **复现步骤**：
  1. 打开编辑器新建文档，在空白行输入 `- 第一项`；
  2. 按 `Enter` 键，光标换到下一行并自动补全 `- `；
  3. 不输入任何字符，直接再次按 `Enter` 键；
  4. **实际结果**：又生成了一行 `- `，文档变为 `- 第一项\n- \n- `。
  5. **预期结果**：当前空列表项的前缀 `- ` 被清除，光标停留在普通段落空行上，退出列表。
- **根因分析（第一性原理）**：
  - 代码位于 `packages/renderer-codemirror/src/wysiwyg/markdown-commands.ts` 中的 `insertListContinuationFallback` 与 `isListContinuationCandidate`。
  - 函数只判断了“光标是否位于列表行末（`head < line.to - 1`）”，**但没有判断当前行除了 marker 以外是否还有实际正文**。
  - 当当前行仅包含列表 marker 时，它仍然被判定为合法的续行候选（candidate），从而无条件 dispatch 了 `\n${indentation}${markerText}`。
- **推荐修复方案**：
  在 `isListContinuationCandidate` 或 `insertListContinuationFallback` 中增加检测：如果当前行除了列表 marker（以及其后的前导空白）外没有其他文字（即属于空列表项），则不插入新列表项，而是执行删除当前行 marker 的操作（将该行重置为空段落行），从而自然退出列表。

### Bug 2: 引用块（Blockquote）在空行回车无法退出引用

- **严重程度**：中
- **现象描述**：
  在引用行 `> 一段引用` 末尾按 `Enter`，会生成 `> ` 续行；但在空的 `> ` 引用行再次按 `Enter`，不会清除 `>` 退出引用，而是继续插入新的引用行 `>\n> `。
- **复现步骤**：
  1. 输入 `> 引用文字`，按 `Enter`；
  2. 光标到达新的一行 `> `；
  3. 再次按 `Enter`；
  4. **实际结果**：继续追加引用层级，生成 `>\n> `。
  5. **预期结果**：清除空的 `> `，退出引用块回到普通行。
- **根因分析**：
  - 与 Bug 1 相同，CM6 原生的 `insertNewlineContinueMarkup` 在受保护模式与自定义 keymap 拦截下，未处理空引用行双回车退出的状态回退。

---

### Bug 3: 快捷键冲突：全局命令面板拦截了编辑器内插入链接快捷键（`Cmd/Ctrl+K`）

- **严重程度**：中
- **现象描述**：
  - `packages/renderer-codemirror/src/wysiwyg/markdown-formatting.ts` 中将 `Mod-k` 注册为 `insertOrWrapLink`（将选中文本包装为 `[选中文本](url)`，或在光标处插入 `[](url)`）。
  - 但 `apps/desktop/src/app/App.tsx` 中在 `window` 上注册了全局 keydown 监听：按下 `Cmd+K` / `Ctrl+K` 时直接 `event.preventDefault()` 并打开全局命令面板（Command Palette）。
  - 这导致编辑器内置的 `Mod-k` 链接格式化命令被完全遮蔽，用户在编辑正文时按 `Cmd+K` 无法插入链接，只能唤出命令面板。
- **复现步骤**：
  1. 在编辑器中选中文本 `my link`；
  2. 按 `Cmd+K`（macOS）或 `Ctrl+K`（Windows/Linux）；
  3. **实际结果**：弹出命令面板弹窗，文本没有被包装成 `[my link](url)`。
- **推荐方案**：
  - 明确快捷键分工：若 `Cmd+K` 作为全局 Command Palette 入口（现代 IDE/桌面软件惯例），则可在命令面板中提供“插入链接 (Insert Link)”命令，并为编辑器内直接插入链接分配标准或备选快捷键（例如 `Cmd+Shift+K` 或 `Cmd+L`），避免两层按键注册冲突。

## 3. 交互不流畅 / 体验摩擦点 (UX Friction)

### Friction 1: 表格最后一个单元格按 Tab 键无法自动追加新行

- **交互卡点表现**：
  - 在 GFM 表格内，用户可以通过 `Tab` 键在单元格之间流畅横向移动，并在行末自动折行到下一行首列。
  - 但当编辑到**表格最后一个单元格（最后一行最后一列）**时，按下 `Tab` 键没有任何反应（既不跳出表格，也不增加新行）。
  - **对比与行业惯例**：在 Notion、Obsidian、Typora、GitHub Issue 以及 Excel / Word 中，在表格末格按 `Tab` 键的标准行为是**自动在表格底部追加一个新行，并将焦点移动到新行的第一个单元格**。当前缺失该行为，导致用户连续录入多行表格数据时，必须停下打字去用鼠标点击行手柄中的“在下方插入行”，打断连续输入。
- **优化建议**：
  在 `packages/renderer-codemirror/src/wysiwyg/table-editing.ts` 的 `navigateTableCell` 中，当检测到目标单元格超出 `maxRow` 且方向为 forward 时，触发 `insertTableRowBelow` 自动新增一行，并将编辑状态置于新行第 0 列。

---

### Friction 2: 空光标状态下缺少成对符号（引号/括号/代码反引号）自动补全闭合

- **交互卡点表现**：
  - 当前 `packages/renderer-codemirror/src/wysiwyg/smart-pairs.ts` 实现了**选区包裹**（例如选中单词按 `*` 变为 `*word*`，按 `[` 变为 `[word]`），体验顺畅。
  - 但在**空光标（无选区）普通打字状态**下，用户输入 `"`、`(`、`[`、`` ` `` 时，编辑器**不会自动补全右侧闭合符号**，也没有输入闭合符号时的跳过（step-over）支持。用户每次输入成对符号都必须完整敲击左右两侧，略显生硬。
- **优化建议**：
  将 CodeMirror 官方成熟的 `@codemirror/autocomplete` 中的 `closeBrackets()` 扩展或定制的空光标成对补全规则引入到 WYSIWYG 扩展链中。

---

### Friction 3: 标题级别切换控件与行首手柄的菜单层级收敛

- **交互卡点表现**：
  - 代码库中存在 `packages/renderer-codemirror/src/wysiwyg/head-level-control.ts`（用于在标题行首显示小号 `H1` 标签并点击下拉切换级别），但该 extension 未被挂载。
  - 当前真实的标题级别切换收敛在每行的 **`⋮` 块操作菜单** 中（悬停行首显示 `⋮`，点击展开包含“添加块”、“折叠”以及 `H1`~`H6`、“正文”）。
  - **体验现状**：用户在标题行打字时，行首没有显式的标题级别提示，必须通过鼠标悬停并点击 `⋮` 才能看到当前可切换的级别。
- **优化建议**：
  清理废弃的孤立代码文件，或者在标题行编辑态弱提示当前级别（如在光标激活标题行时显示轻量级别标签），并提供 `Mod-Alt-1` ~ `Mod-Alt-6` 的快捷切换（目前 `markdown-formatting.ts` 已有该命令，需确保在 UI 提示中露出）。

## 4. 体验优良与设计亮点记录

1. **单 View 架构无缝体验**：
   - WYSIWYG 模式与源码模式切换毫无割裂感，光标在同一行同一点，选区高亮不变，撤销历史不丢失。
2. **表格 GFM 源码转义防护**：
   - 单元格内输入包含管道符 `|` 的文字时，底层自动转义为 `\|`，无论怎么编辑单元格内容，都不会破坏 GFM 表格的多列结构。
3. **大纲面板双向联动**：
   - 大纲面板实时解析文档各级标题，点击标题秒级精准滚动居中；滚动编辑区时，大纲自动跟踪当前最近的标题并更新 `aria-current="location"` 状态。
4. **代码块隔离与纯净复制**：
   - 代码块右上角提供语言快速切换与独立 Copy 按钮，复制内容仅包含代码正文，不带外层反引号与语言标记。
5. **块级拖拽重排**：
   - 六点手柄支持平滑 pointer 拖拽，并提供实时蓝色落点指示线，松开后精准更新段落顺序。
