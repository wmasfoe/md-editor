# 自定义图片相对路径解析与目录拦截规范

> 状态：桌面端与文件系统当前契约。v0.10.0 引入，v0.10.1 验证通过（PR #55）；支持 `./`、`../` 与 `${filename}` 相对路径，未存在目录弹窗拦截授权。

## 用途

记录粘贴图片、拖拽插入图片时的目标路径解析、动态文件名变量替换，以及底层文件系统目标目录缺失时的防御性交互契约。修改图片保存逻辑、路径处理或文件服务前先读本规范。

---

## 核心不变量

### 1. 相对路径解析与跨端正斜杠标准

- 支持类似 Typora 的相对路径配置体系：
  - 以 `./` 开头：表示相对于当前正在编辑的 Markdown 文档所在同级目录（例如 `./assets`）；
  - 以 `../` 开头：表示相对于当前 Markdown 文档父级目录（例如 `../assets`）；
  - 绝对路径：直接定位至用户指定的本地绝对目录。
- **跨平台路径正斜杠不变量**：无论宿主操作系统是 macOS、Linux 还是 Windows，生成并插入到 Markdown 文档中的图片相对链接 `![alt](path)` 必须统一使用正斜杠 `/`，杜绝 Windows 反斜杠 `\` 导致文档在跨平台流转时链接失效。

### 2. `${filename}` 动态占位符契约

- 图片存储路径配置支持嵌入 `${filename}` 动态变量：
  - 必须动态解析为当前正在编辑的 Markdown 文档的基础文件名（去除扩展名，例如 `my-note.md` -> `my-note`）；
  - 配置示例：`./assets/${filename}` -> 落地为当前文档同级的 `./assets/my-note/` 目录；
- 若当前文档为尚未命名的空白草稿文档（filePath 为 null），系统必须优雅回退至安全的默认占位目录，严禁解析出 `undefined`、空字符或抛出异常。

### 3. 未存在目标目录防御性拦截授权契约

- 当图片保存服务检测到目标解析目录在本地物理磁盘上尚不存在时：
  - **严禁静默创建**：不可擅自在用户未感知的情况下在工作区内建立新文件夹；
  - **严禁静默失败**：不可直接报错吞掉用户的图片输入；
  - **模态拦截授权**：必须主动调用系统模态确认弹窗（“尝试将新插入的图片复制到目录 ...。但该目录不存在，是否立即创建？”）；
  - 用户明确授权确认后，系统才可递归建立各级目录（`mkdir -p`）并持久化图片资源；若用户点击取消，则安全终止本次图片插入，保持文档原状。
