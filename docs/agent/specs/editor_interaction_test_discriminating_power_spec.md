# 编辑器交互测试的区分力规范

> 状态：生效。适用于 `packages/renderer-codemirror/tests/**` 与 `apps/desktop/e2e/**` 里所有断言「光标位置、按键接管、DOM 行结构」的测试。

## 用途

记录一条原则和一套做法：**测试通过不等于测试守住了行为**。一条用例如果把实现改坏后仍然通过，它对该行为没有区分力。本规范给出怎么发现、怎么补、怎么留证据。

起因：为文末虚拟空行补测试时，反复出现「用例全绿，但回滚实现后仍全绿」。这些用例当时看起来合理，没有一条是靠读代码发现的缺口，都是破坏实现后才暴露。

触发阅读的改动范围：

- 新增或修改断言光标位置（`selectionHead`、`selection.main`）、按键是否被接管（`defaultPrevented`、文档是否变化）、`.cm-content` 子节点结构的测试；
- 为某个修复补回归测试；
- code review 时判断「这条测试是否真的守住了这个修复」。

配套规范：[WYSIWYG 文末虚拟空行规范](./wysiwyg_virtual_trailing_line_spec.md)里的每条踩坑都对应本规范的一个模式。

---

## 一、核心原则

1. **回归测试必须在修复被撤销时失败。** 补完测试后，把实现改回旧版本（或把关键一行改坏），测试必须变红；然后还原。没做过这一步的测试，只能说「通过」，不能说「守住」。
2. **夹具要让「要测的两个量」真的不同。** 断言 `A === B` 的用例，如果夹具让 `A` 与 `B` 恒相等，它什么也测不出。
3. **断言对象要换成能区分的观测量。** 某个绑定的作用在当前环境观察不到，就如实写明覆盖范围，不要用一条永远通过的断言假装覆盖。
4. **页面上的事实优先于代码注释。** 「这里有没有一行」「光标落在哪」要在真实浏览器里量，不要从注释推断。

---

## 二、做法：变异验证

对一条实现逐项制造「看起来合理的错误」，跑测试，记录哪些被拦住。

```bash
cp src/…/impl.ts /tmp/impl.orig.ts
python3 - "<旧片段>" "<新片段>" <<'EOF'      # 必须 assert 旧片段存在，防止替换静默落空
…
EOF
pnpm exec vitest run tests/…                 # 期望：至少有一条变红
cp /tmp/impl.orig.ts src/…/impl.ts           # 还原；git diff --quiet 确认
```

要点：

- **替换前断言片段存在**（`assert s.count(old) == 1`）。否则替换落空，实现没变，测试「通过」会被误读为拦住了。
- **每次变异后还原**，并在最后确认工作区干净。不要在带着变异的状态下继续写别的东西。
- **变异体要有语义**：「改回旧实现」「去掉某个守卫」「读旧值代替新值」「放宽条件」，不要随机改字符。
- **未被拦住的变异体要分类处理**，见下一节。不能只记结果。

### 未被拦住时的三种结论

| 结论 | 判据 | 处理 |
| --- | --- | --- |
| 漏测 | 变异体改变了用户可见行为，测试没发现 | 补用例，再跑同一变异体确认被拦住 |
| 夹具缺陷 | 行为在别的输入下会变，但当前夹具恒相同 | 换夹具（见模式 1、2），不是加断言 |
| 等价变异 | 变异体在所有可达输入下行为相同（例如外层已预先限定） | 在规范里登记「已确认等价」及理由，不补用例 |

「等价」必须有证据（调用点唯一、外层条件已限定），不能因为补不出用例就宣布等价。

## 三、本次遇到的六个模式

### 模式 1：两个偏移恒相等

**现象**：断言「光标停在文档末尾」的用例，把实现改回「停在块末端」仍通过。

**原因**：夹具文档没有尾随换行，此时块的 `fullRange.to === doc.length`，两个位置是同一个数。

**做法**：夹具带尾随换行，并在用例开头**前置断言两个量不等**：

```ts
expect(record.fullRange.to).toBeLessThan(view.state.doc.length);
```

前置断言让用例自己证明「我有区分力」，将来有人改夹具去掉尾随换行，它直接报错而不是悄悄失效。

### 模式 2：另一个处理器也会得到同样结果

**现象**：删掉虚拟行对 `ArrowLeft` 的绑定，「ArrowLeft 回到上一块」的用例仍通过。

**原因**：夹具里光标在块末端，仓库另一层（原子选择）对同一按键也会选中该块。

**做法**：换夹具让只有被测绑定能产生该结果（带尾随换行，光标在 `doc.length`），并用 `it.each` 覆盖 table / html / thematic-break。

### 模式 3：保护层掩盖了被测行为

**现象**：去掉 `Backspace` / `Delete` 的键位绑定，文档与事务数都不变。

**原因**：文末的删除同时被 `wysiwygChangeProtection` 拦下。绑定的真实作用（避免提示「需要切换源码模式」）在 jsdom 里观察不到。

**做法**：只守能守住的不变量（「文档不变」），在用例旁**写明覆盖范围**；有区分力的键（`Enter`，需装 `defaultKeymap`）单独成例。不要为了「覆盖」而写永远通过的断言。

### 模式 4：夹具缺默认键位

**现象**：「Enter 不改文档」的用例，删掉绑定后仍通过。

**原因**：测试夹具没装 `defaultKeymap`，合成的 `Enter` 本来就什么都不做。

**做法**：夹具提供可选的 `extraExtensions` 参数，需要时装上与生产根扩展一致的默认键位。要测「我的绑定压过默认键位」，默认键位必须在场。

### 模式 5：用 `defaultPrevented` 判断「有没有被接管」

**现象**：「空剪贴板时不接管粘贴」断言 `event.defaultPrevented === false`，失败。

**原因**：CM6 自带的 `paste` 处理器对空剪贴板也会 `preventDefault`。

**做法**：改看**结果**（文档是否变化、激活态是否改变），不看事件标志。

### 模式 6：夹具默认状态改变了被测对象

**现象**：断言 HTML 块是预览态，却拿到源码态（找不到 widget）。

**原因**：夹具默认把光标放在 `doc.length`，贴文末的 HTML 块因此展开成源码行。

**做法**：用例开头显式把光标放进开头的正文，再断言。夹具的默认选区是被测状态的一部分，不要假设它是中性的。

## 四、浏览器 e2e 的补充要求

1. **回归用例要在旧实现上失败**，同样用「改回旧实现 → 跑 → 还原」验证。`VTL-11` 就是这样确认的（旧实现上表格两条收到 2 行）。
2. **量结构，不量像素**：断言 `.cm-content` 直接子节点的序列与类型，而不是具体 y 坐标。像素随主题与字体变。
3. **探针脚本放临时文件，用完删除**。不要把一次性探针留在 `e2e/` 里，也不要提交。
4. **jsdom 单测与 Chromium e2e 各守一层**：jsdom 守逻辑、状态和 DOM 结构，e2e 守真实布局。CM6 的行构建在 jsdom 里同样会执行，所以「块下方有几个直接子节点」这类**结构**断言两边都能写（本次单测与 `VTL-11` 就是各写了一份，且都在旧实现上失败）；高度、点击坐标、光标绘制位置只能在 e2e，jsdom 不做布局。
5. **桌面专属行为不可由 Chromium e2e 代表**：真实 Tauri 窗口里的 IME 组字、原生菜单、系统剪贴板，只能手测，不得把「e2e 全绿」说成「桌面端已验证」。

## 五、PR 与评审里怎么表述

写回归测试的 commit 或 PR 描述里，写出**回滚验证的结果**，不要只写「新增测试」：

> 已验证：把光标改回 `record.fullRange.to`，三条用例均失败（33≠34、14≠15、9≠10）。

评审者看这句话，就知道这些用例有区分力。没有这句话的回归测试，评审者应当追问。

---

## 六、范围外

- 不要求对所有历史测试补变异验证。只要求**新增的回归测试**与**修改了行为的测试**做；
- 不引入自动化变异测试工具。手工变异在这个规模下足够，引入工具需要单独评估收益与维护成本；
- 本规范不规定覆盖率数字。覆盖率衡量「跑过哪些行」，区分力衡量「改坏后会不会发现」，二者不同。
